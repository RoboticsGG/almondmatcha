## Field POC Readiness Assessment

### Single-domain branch — Field POC: READY (one blocker)

**What's in place:**
- `ws_base/launch_poc_field.sh` — orchestrates RPi + Jetson + base from one command on the base PC via SSH
- Emergency `Ctrl-C` kills all remote nodes and local collectors instantly
- Live D415 camera required — correct for field (no video-file fallback)
- `ws_base/params/field/` — operator-editable YAML for GPS coords, speed limit, camera config, PID gains (edit before run, no need to touch `src/`)
- `POC_SINGLE_DOMAIN.md` — full measurement guide with clock sync checklist

**One remaining blocker — STM32 firmware not yet flashed:**

The serial mutex fix (session 2026-05-22, commit `512053f`) was **committed but never reflashed** to the boards.
Without the fix the boards are still running the pre-fix firmware where each `.cpp` translation unit that includes `memory_reporter.h` gets its own `static Mutex` copy → `gnss_reader.cpp` locks a *different* mutex than `_mr_task()` → serial output can be interleaved/corrupted → STM32 JSON collector produces corrupted records.

**This corrupts the STM32 measurement columns in `merged_all.csv` — must fix before taking data.**

Reflash commands (run from `single-domain` branch):
```bash
# Sensors-GNSS board (192.168.1.6)
cd ~/almondmatcha/mros2-mbed-sensors-gnss
sudo ./build.bash rebuild NUCLEO_F767ZI sensors_node
sudo openocd -f interface/stlink.cfg -f target/stm32f7x.cfg \
  -c "hla_serial 066DFF3932504E3043014542" \
  -c "reset_config srst_only connect_assert_srst" \
  -c "program build/mros2-mbed.bin verify reset exit 0x08000000"

# Chassis-dynamics board (192.168.1.2)
cd ~/almondmatcha/mros2-mbed-chassis-dynamics
sudo ./build.bash rebuild NUCLEO_F767ZI chassis_controller
sudo openocd -f interface/stlink.cfg -f target/stm32f7x.cfg \
  -c "reset_config srst_only connect_assert_srst" \
  -c "program build/mros2-mbed.bin verify reset exit 0x08000000"
```

### The "ease of use" gap

**Main requires manually SSHing to each machine and running scripts in order.**  
There is no single orchestrating command on the base PC that brings up the full system.

The SDM/MDM field scripts already solve this problem for the measurement case.  
Main needs an equivalent `launch_field.sh` (no measurement overhead) that:
1. SSHs to RPi → runs `launch_rover_tmux.sh`
2. SSHs to Jetson → runs `launch_headless.sh`
3. Starts `launch_base_tmux.sh` locally
4. Provides `Ctrl-C` emergency stop (kills all remote sessions)
