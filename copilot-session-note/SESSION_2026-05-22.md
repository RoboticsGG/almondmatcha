### 2. Mutex Singleton Fix (commit `512053f` → cherry-picked `a1f620a`)
**Problem found:** `_mr_stdout_mtx` was `static Mutex` in a header — each `.cpp` that includes the header gets its own copy. `gnss_reader.cpp` locked a *different* mutex than `_mr_task()` in `app.cpp` → no actual serial protection.

**Fix applied to both `memory_reporter.h` files:**
```cpp
// Before (wrong — per-TU copy):
static Mutex _mr_stdout_mtx;
inline void mr_serial_lock()   { _mr_stdout_mtx.lock(); }
inline void mr_serial_unlock() { _mr_stdout_mtx.unlock(); }

// After (correct — function-local static, one instance across all TUs):
inline Mutex& mr_serial_mutex() { static Mutex m; return m; }
inline void mr_serial_lock()   { mr_serial_mutex().lock(); }
inline void mr_serial_unlock() { mr_serial_mutex().unlock(); }
```
Also updated `_mr_task()` body to call `mr_serial_lock()`/`mr_serial_unlock()` instead of direct `_mr_stdout_mtx.lock()`.

## Critical: Base PC Environment

**The base PC has TWO NICs:**
- `enp0s31f6` — 192.168.1.4 (rover LAN)
- `wlp4s0` — WiFi (internet)

FastDDS defaults to WiFi → STM32 SPDP multicast invisible → `ros2 topic list` shows no STM32 topics.

**Must set in every terminal (or add to `~/.bashrc`):**
```bash
export ROS_DOMAIN_ID=5
export FASTRTPS_DEFAULT_PROFILES_FILE=$HOME/almondmatcha/ws_base/fastdds_base.xml
```
After setting in a running shell:
```bash
ros2 daemon stop && ros2 daemon start
ros2 topic list   # STM32 topics should now appear
```
Verify SPDP multicast (domain 5 port = **8650** = 7400 + 250×5):
```bash
sudo tcpdump -i enp0s31f6 'dst host 239.255.0.1 and udp port 8650' -nn -c 3
```
